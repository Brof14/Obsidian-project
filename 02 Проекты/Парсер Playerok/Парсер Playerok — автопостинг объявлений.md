# 🤖 Автоматическое размещение товаров на Playerok.ru

> Промпт-спецификация для production-проекта на Playwright, автоматизирующего размещение объявлений (Steam-аккаунты по списку игр) на playerok.ru.

## Роль и требования к коду

Production-ready: Python 3.12+, полная типизация, PEP8, SOLID, `dataclasses`, `pathlib` вместо `os.path`, `logging`, `asyncio`. Без TODO и псевдокода — готовность к реальному использованию после настройки селекторов.

## ⚠️ Критические ограничения (важно!)

Сайт использует авторизацию через код подтверждения. **Запрещено:**
- автоматически получать SMS-коды
- автоматически получать email-коды
- использовать OCR
- использовать сервисы решения капч
- обходить механизмы подтверждения личности

**Разрешено:**
- использовать сохранённую пользовательскую сессию
- подключаться к уже авторизованному браузеру через CDP
- восстанавливать cookies / localStorage / sessionStorage

Если сессия недействительна — скрипт должен остановиться с сообщением: *«❌ Сессия истекла. Выполните ручной вход через save_session.py и сохраните новую сессию»*.

## Режимы работы

- **Обычный:** `python main.py input.txt`
- **CDP (приоритетный):** `python main.py input.txt --cdp http://localhost:9222` — пользователь сам запускает `google-chrome --remote-debugging-port=9222`, после ручной авторизации скрипт подключается к открытому браузеру
- **Dry run** (`--dry-run`): браузер не открывается, публикация не выполняется, выводятся итоговые данные по каждой игре

## Входные данные

Два источника:
1. **Локальный TXT** — формат: `Логин: ...`, `Платформа: PC`, `Игры:` (список через перенос строки или запятую)
2. **Google Docs** — через `google-api-python-client`; если `credentials.json` отсутствует — подробная инструкция настройки, затем автопереключение на локальный режим

Парсинг игр: всё после строки `Игры:`, разделители — новая строка или запятая, пустые строки игнорируются. Результат: `{"login": "...", "platform": "...", "games": [...]}`.

## Сохранение сессии (`save_session.py`)

1. Открыть браузер → playerok.ru
2. Ждать ручной авторизации пользователя
3. По нажатию Enter сохранить cookies / localStorage / sessionStorage в `session.json`

## Проверка авторизации

Перед началом работы — открыть профиль, убедиться в авторизации. Если обнаружены форма входа / запрос кода / подтверждение / капча — остановить выполнение с сообщением *«❌ Требуется ручная авторизация»*.

## Human-like поведение

`random_delay()`, `human_like_mouse()`, `human_like_scroll()` перед каждым кликом. Между объявлениями — 120–300 секунд (`asyncio.sleep`, не `time.sleep`), после каждых 3 объявлений — длинная пауза 600–900 секунд.

## Генерация контента объявления

- **Название:** шаблон `💥{bold_game_name} (Steam Аккаунт)✅НАВСЕГДА✅ГАРАНТИЯ`
- **`to_math_bold()`:** латиница и цифры → математический жирный Unicode; кириллица, пробелы, дефисы и спецсимволы не меняются (пример: `Spider-Man` → `𝗦𝗽𝗶𝗴𝗲𝗽-Man`)
- **`clean_game_name()`:** удаляет из имени конструкции вида «(все части)»

## Описание и комментарий (выносятся в `config.py`)

`DESCRIPTION_TEMPLATE` — приветственный текст магазина с пунктами (лицензионный аккаунт, гарантия, сохранение прогресса, офлайн-игра, платформа Steam) и предупреждением о передаче попыток обмана администрации.

`COMMENT_TEMPLATE` — благодарность за покупку с просьбой поставить 5 звёзд.

## Категория и поля формы

`select_category(page, category_path)` с путём `["Игры", "Аккаунты Steam"]`, через `get_by_role()` / `get_by_text()` / `scroll_into_view_if_needed()` — без динамических CSS-классов.

Поля: Название, Описание, Комментарий, Категория, Платформа, Способ передачи, Данные аккаунта, Цена, Фотографии, Бесплатное размещение.

Для данных аккаунта используется только логин из входного файла — **пароль пользователя Playerok не используется**.

## Работа с изображениями

Папка `images/`, поддержка `GameName.png/.jpg/.webp`, `GameName_1.png` и т.д., либо `images/GameName/`. При отсутствии фото — `logger.warning(...)` и продолжение работы.

## Публикация, retry, восстановление после сбоев

- Поддержка кнопок «Опубликовать» / «Сохранить» / «Готово», ожидание уведомления или редиректа, таймаут 30 секунд
- До 3 попыток с экспоненциальной задержкой (2с → 4с → 8с)
- При сбое (браузер упал / соединение оборвалось / вкладка закрылась) — перезапуск браузера и продолжение с текущей игры
- Прогресс в `progress.json` (`{"completed": [...]}`) — завершённые игры повторно не публикуются

## Обработка капчи

При обнаружении Turnstile / CAPTCHA / проверки безопасности / подтверждения входа — остановка с сообщением *«❌ Требуется ручное вмешательство»*, ожидание до 5 минут, продолжение после подтверждения пользователем.

## Селекторы

Словарь `SELECTORS = {...}` для всех элементов интерфейса. Не использовать React/Tailwind-классы или динамические классы — только устойчивые локаторы (`get_by_role()`, `get_by_text()`, `get_by_label()`, `get_by_placeholder()`).

## Логирование

Файл `posting.log`, формат `[2026-06-06 12:34:56] INFO Spider-Man опубликован`, параллельный вывод в консоль. При ошибках — скриншот в `screenshots/error_*.png`.
