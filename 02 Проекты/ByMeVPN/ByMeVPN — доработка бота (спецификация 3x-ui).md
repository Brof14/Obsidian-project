# 🛠 ByMeVPN — доработка бота (спецификация интеграции с 3x-ui)

Промпт-спецификация для приведения в порядок интеграции бота с панелью 3x-UI Reality через библиотеку `py3xui`. Взято из Telegram «избранное» (19.03.2026).

## 1. Критические проблемы (исправить первыми)

**1.1. Удалить вредный код, ломающий протокол** — где-то в проекте `https://` принудительно заменяется на `http://`, что вызывает `UnknownProtocol('HTTP/0.0')` и делает подключение к панели невозможным. Убрать замену протокола полностью, использовать `self.host` как есть.

**1.2. py3xui должен работать по HTTPS** — добавить поддержку HTTPS, `verify=False` (самоподписанный сертификат), не менять и не переписывать URL автоматически.

**1.3. Поддержка кастомного пути панели** — панель работает по адресу вида `https://<host>:<port>/<random-path>/`, py3xui должен корректно добавлять этот путь ко всем запросам.

**1.4. Ошибка Pydantic** — `settings.clients.0.tgId — Input should be a valid string`. Причина: `tgId` отправляется как `int`. Исправить сериализацию → `tgId` должен быть строкой.

## 2. Архитектурные проблемы (второй приоритет)

- Бот асинхронный, `py3xui` — синхронный, что блокирует event loop. Нужно обернуть все вызовы `py3xui` в `asyncio.to_thread()` или сделать асинхронные обёртки.
- Переписать `xui_manager.py`: корректный HTTPS, кастомный путь, асинхронные вызовы, обработка ошибок, retry-логика, генерация UUID и VLESS Reality ключа.
- Переписать `subscription_core.py`: `add_client()` → `await`, асинхронный retry, обработка ошибок панели, корректное сохранение ключей в БД.

## 3. Логика выдачи ключей (третий приоритет)

- Исправить создание клиента: inbound читается → UUID создаётся → клиент добавляется.
- VLESS Reality ключ должен включать: `uuid`, reality settings, `sni`, `fp`, `pbk`, `sid`, `host`, `port`.
- Исправить сохранение ключей в БД (создать таблицу `keys`, если её нет).

## 4. Пробный период (новая функция)

- Длительность: 3 дня, ограничение: 1 устройство, доступен только 1 раз на пользователя.
- Если пробный период уже использован → показывать сообщение и не выдавать ключ.
- Пробный ключ создаётся через тот же API-клиент.

## 5. Админ-панель (новые функции)

Функция возврата звёзд: выбрать пользователя → указать количество звёзд → вернуть на баланс → логировать операцию → показывать историю возвратов.

## 6. Мелочи и полировка

- Единый формат путей к панели, убрать дублирование логики, единый стиль логов.
- Обновить тесты под новый API-клиент: успешная выдача ключа, панель недоступна, панель возвращает ошибку, UUID не создан, retry работает, пробный период работает, рефералы работают, оплата работает, возврат звёзд работает.

## Цель

После всех исправлений бот должен: корректно подключаться к панели по HTTPS, использовать `py3xui` (адаптированный), работать асинхронно, создавать клиентов, выдавать ключи и пробный период, поддерживать возврат звёзд, работать стабильно.
